The idea

From chatbot to action layer.

Rajjo started as an experiment in moving conversational AI from “answering” to “doing.” For the first eight weeks, the scope is intentionally narrow: WhatsApp text/voice input, meeting scheduling, email actions, live web search, lightweight session context, and confirmation before external actions. The goal is not to build a universal assistant in eight weeks — it is to prove that a small set of high-frequency workflows can save users meaningful time.

Capabilities

One conversation. Multiple tools.

01 / INPUT

Text + Voice

Accepts conversational requests through WhatsApp, including voice notes converted into actionable instructions.

02 / CONTEXT

Conversational Memory

Maintains context so follow-up instructions can build naturally on what was discussed before.

03 / SEARCH

Live Web Search

Routes time-sensitive questions to live search instead of relying only on static model knowledge.

04 / COMMUNICATION

Email Actions

Structures and prepares email actions, with confirmation before executing sensitive outbound communication.

05 / PRODUCTIVITY

Calendar Scheduling

Understands dates, times, duration and attendees to turn natural requests into calendar events.

06 / SAFETY

Human Confirmation

Keeps the user in control by inserting explicit confirmation before selected real-world actions are executed.

8-week MVP

Build less. Validate faster.

The first version of Rajjo is deliberately constrained. Advanced autonomy, a standalone Android app, wake-word activation, and broad third-party integrations are outside the eight-week MVP.

IN SCOPE

What gets built

WhatsApp text + voice input, three core workflows (calendar, email, live search), lightweight per-user context, explicit action confirmation, basic logs, retries and failure messages.

NOT YET

What waits

Android app, wake word, unrestricted agent autonomy, dozens of integrations, complex long-term memory, enterprise administration, and large-scale infrastructure.

Architecture

Listen → understand → decide → act.

Rajjo is designed around an intelligence and action architecture. Incoming requests are interpreted, enriched with context, and passed to an Action Engine that selects and orchestrates the right workflow across connected tools and services.

Buildability

Production concerns are part of the MVP.

The eight-week version does not attempt internet-scale architecture. It focuses on a controlled pilot while explicitly addressing the failure modes that matter even at small scale.

AuthenticationUse provider-supported OAuth/token flows and keep credentials isolated from conversational data.
API limitsTrack quotas, minimise unnecessary calls, use bounded retries/backoff, and return clear fallback messages when a provider is unavailable.
Error handlingValidate tool inputs before execution, log workflow failures, and never silently claim an action succeeded.
Multi-user stateKey short-lived conversation state by WhatsApp user ID so one user's context cannot leak into another user's session.
ConfirmationEmail and calendar actions pass through a confirmation checkpoint before external execution.
Business model

Start with paying individuals. Learn where the strongest pull is.

The initial hypothesis is a paid productivity assistant for busy students and early-career professionals who already live on WhatsApp and repeatedly switch between search, email and calendar tools. Pricing is a validation hypothesis — not a proven business model yet.

PAYER

Individual user

Students and young professionals with recurring scheduling, email and information-retrieval workflows.

PRICING TEST

₹199–₹299 / month

A simple early-access subscription. The test is whether convenience and time saved are valuable enough for users to pay.

ACQUISITION

Founder-led pilot

Recruit the first cohort through campus and professional networks, onboard users directly, observe usage, and use referrals before paid acquisition.

Path to first revenue

Eight weeks to a real payment, not an oversized roadmap.

Weeks 1–2 · Narrow the problemInterview target users, identify repeated workflows, lock the three-action MVP, and recruit a small design-partner cohort.
Weeks 3–4 · Make the core reliableStabilise WhatsApp input, calendar, email and search flows. Add confirmations, session isolation, logs, basic retry handling and usage instrumentation.
Weeks 5–6 · Controlled pilotPut Rajjo in the hands of a small cohort. Track successful task completion, repeat usage, failures, and which workflow creates the most value.
Week 7 · Ask users to payOffer the most engaged pilot users a ₹199–₹299 early-access plan and capture objections instead of assuming willingness to pay.
Week 8 · Revenue checkpointTarget at least one paying user. Review retention signals, API cost per active user, workflow reliability and payment feedback before expanding scope.
First milestone: 1 paying user.

Success at this stage means proving somebody values Rajjo enough to pay — not pretending the product is already ready for mass scale.

Design philosophy

Useful AI should reduce steps, not add another app to manage.

A

Natural first

Users describe the outcome they want instead of learning commands, menus or rigid syntax.

B

Action oriented

The conversation is only the interface. The real value comes from connecting intent to execution.

C

Control by design

Autonomy is paired with checkpoints so consequential actions remain visible and deliberate.

Post-validation vision

Rajjo beyond WhatsApp.

Only after the WhatsApp MVP demonstrates repeat usage and willingness to pay would Rajjo expand toward a standalone mobile assistant, deeper device integration, wake-word interaction and a broader action ecosystem.
